# FloRA functional build first

The owner prioritizes the complete FloRA causal prototype before latency work.
Verify its required memory, Experience, state, mission and outcome connections;
obtain credible evidence for its hypothesis; then optimize toward frontier-level
latency. Personality and MFM remain external. This does not expand FloRA into
the full Alice platform.

## Build sequence

1. **Freeze the capability claim.** Relevant correction/outcome changes later
   judgment for the right reason; irrelevant changes preserve judgment. Full,
   general-memory and same-evidence ablation arms receive equal authorized
   originals. Functional fixtures prove connections; qualified external outputs
   and independent evaluation are needed for credible learned results.
2. **Preserve completed evidence.** Run37641323381 has one physical pass and two
   fixture-budget failures on exact sourcebd731095/Alice4f287a.81 components pass.
   Keep the logs, old10s/60s verdicts and unqualified900s observation alarm.
   Stop latency-only patches, profiling campaigns and performance gates as build
   prerequisites. A configured-limit failure is not a calibrated product verdict.
3. **Use existing canonical links.** Trace authorized originals/Experience to
   admitted Claim/state, selected context, external native judgment, recorded
   decision/action, outcome/correction and governed revision. Keep scoped source
   identities, causal parents, generations and current permissions connected.
   Add a mission/result link only where the actual scenario requires it.
4. **Connect the missing same-case execution.** Reuse one actual registered
   two-stage history, sealed BEFORE and qualified AFTER. Supply the existing two
   NativeArmAdapter ports and GeneralMemoryArmAdapter to the actual
   RegisteredExperimentCoordinator. Persist all six attempts, including failures;
   assert exact originals, context equality, treatment routing and chronology.
5. **Separate functional completion from speed.** Declare a distinct mechanical
   test protocol with bounded execution/resource containment. Preserve cancellation,
   backend deadlines, current H/C authority, immutable invocation IDs and required
   writes. Its limit contains a run; it does not score speed. Keep historical
   performance cases/versioned results intact; do not turn them green by relabeling.
6. **Verify meaningful controls.** First complete an authorized operation, then
   reach the exact intervention/tampering point. Independently withdraw history
   or context authority and assert no later forbidden read/dispatch/append. Recover
   exact persisted attempts without new inference, provider dispatch or replayed
   writes. Use distinct run identities for negative variants.
7. **Complete the causal prototype.** Exercise relevant correction, irrelevant
   correction and a decision-linked outcome through that connected path. Plug in
   separately qualified personality/MFM outputs when available. Evaluate baseline
   competence, reason/evidence attribution and the independent assessment before
   claiming hypothesis support. Keep builder transfer as a separate required result.
8. **Optimize latency afterward.** Measure cold construction, warm retrieval,
   authority, inference, durable recording and full response separately. Report
   matched workload/hardware/model conditions, sample counts, median/tail latency
   and failures. Choose comparable budgets through the development pilot and freeze
   them before held-out scoring. Do not copy a competitor's absolute cutoff.

The baseline clock includes cold memory preparation, fresh authorization,
disclosure/capture, dispatch/recording and final checks. The native fixture recovers
pre-created fictional judgments. These are different plumbing fixtures, not a fair
cross-arm latency comparison. The frozen goal requires a pilot and comparable
preregistered budgets; none of these numbers supplies that calibration.

Primary research supports explicit measurement boundaries: Mem0 separates search
and total response latency and reports p50/p95; its numbers are workload-specific.
[Mem0 Table2 and metric definitions](https://arxiv.org/html/2504.19413v1#S3.SS2).
Zep reports model/context-dependent response times, including a31.3s full-context
baseline; this is a study result, not a FloRA deadline.
[Zep Table2](https://arxiv.org/html/2501.13956v1#S4.SS3).
LongMemEval-V2 scores accuracy across a latency frontier rather than one universal
deadline. Its open harness measures query and post-query work separately.
[Leaderboard methodology](https://xiaowu0162.github.io/longmemeval-v2/),
